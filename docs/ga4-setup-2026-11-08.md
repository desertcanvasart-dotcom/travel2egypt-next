# GA4 + conversion tracking: go-live checklist (2026-11-08)

The code is dormant until `NEXT_PUBLIC_GA_MEASUREMENT_ID` is set. Do the steps **in this order**:
the cookie policy promises it will be updated *before* any new tracking goes live.

## 1. In Google Analytics (Admin)

1. **Property → Data streams → Web → travel2egypt.org**: copy the Measurement ID (`G-XXXXXXXXXX`).
   Check that **Enhanced measurement** is on, including *Page changes based on browser history events*.
   The site is a Next.js app, so page changes after the first load are counted this way.
   - In Enhanced measurement, also turn **Form interactions off**. The site has no forms, and the concierge chat box would only add noise.
2. **Data settings → Data retention**: set event data to **14 months**. The default is 2 months, and the policy text says 14.
3. **Data settings → Data collection**: leave **Google signals off**. The code also disables it, and the policy says it is off.
4. **Admin → Data display → Events**: once the events below have appeared (within 24–48 h of going live), mark them as **Key events**:
   - `whatsapp_click`
   - `email_click`
   - `phone_click`
   - `concierge_brief_complete` (the concierge confirmed a full trip brief, i.e. a qualified lead)
   - `concierge_handoff_sent` (the visitor sent the chat to the team)
5. Optional but useful: **Admin → Custom definitions → Create custom dimension** (event scope) for
   `placement`, `link_url`, `tour` and `locale`. This lets reports show *where* on the page people clicked WhatsApp.
6. Also tracked, not key events: `plan_tour_click` (link into /plan-your-tour), `concierge_chat_start`
   and `concierge_trip_saved`. Use them as funnel steps in **Explore → Funnel exploration**:
   page view → `plan_tour_click` → `concierge_chat_start` → `concierge_brief_complete`.

## 2. In Sanity Studio: publish the policy drafts

Unpublished drafts are waiting, in EN/ES/JA. They say Google Analytics is used only with consent, name
the `_ga` cookies, 14-month retention, Google as processor and the DPF/SCC transfer basis, and describe how to withdraw consent:

- **Cookie Policy** (`legal-cookie-policy`): new section "Analytics, only if you agree: Google Analytics",
  plus revised intro, consent-record (`consent-v3`), "don't use" list, "Your choices" and closing lines.
- **Privacy Policy** (`legal-privacy-policy`): new "Website analytics" paragraph after "Error monitoring".

Review them (counsel review is still pending on both docs: `legalReviewStatus` = false), then publish both.
Backup of the published versions before this change: `legal-backup-2026-11-08.json`, in the session scratchpad.

## 3. In Railway: switch it on

Add the variable `NEXT_PUBLIC_GA_MEASUREMENT_ID=G-XXXXXXXXXX` to the web service. Railway redeploys,
and the variable is baked in at build time, so a rebuild is required.

From that deploy on:
- Every visitor is asked once: **Accept analytics / Essential only** (re-prompted because the key moved from `consent-v2` to `consent-v3`).
- Before a choice, or on "Essential only", GA runs in Consent Mode "denied": cookieless pings only, no `_ga` cookie.
- The footer "Cookie preferences" link reopens the choice.

## 4. Verify (10 minutes after deploy)

- GA → **Reports → Realtime**: your own visit appears after you click *Accept analytics*.
- Tap a WhatsApp link: `whatsapp_click` shows in Realtime → *Event count by event name*.
- **Admin → DebugView** works with the Google Tag Assistant browser extension.

## Kill switch

Remove the Railway variable. The next deploy drops GA completely and returns the cookie notice to "Got it".
